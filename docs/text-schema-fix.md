# 模型文字只剩单字：根因与修复

## 根因（当前接口实测确认）

用户提供的原始 JSON 中，节点 `text` 已是单字，图片只是显示该数据。问题发生在模型约束生成阶段。

本地 Pydantic 的非空白约束 `pattern: "\\S"` 原样传给了原生 JSON Schema 模型接口。JSON Schema 的 pattern 是搜索匹配，原意是“包含至少一个非空白字符”；当前兼容接口在生成时表现为完整字符串匹配，使自然语言字段只能生成一个字符。模型提示词要求完整短语也无法绕过这一硬约束。节点、条件、标题和摘要都使用同一非空白规则。

2026-09-11 使用已配置的 qwen3.8-flash 接口，以相同提示词和固定合成短语做最小对照：

| 约束 | 节点文字 | 条件 | 耗时 |
| --- | --- | --- | --- |
| 原始 `pattern: "\\S"` | 接 | 不 | 3.00 秒 |
| 移除这一个 pattern | 接收项目需求 | 不合格 | 3.63 秒 |

这是当前接口的观察结果，未推断供应商内部使用的具体解码框架。JSON Schema 的标准搜索语义见 [官方字符串 pattern 文档](https://json-schema.org/understanding-json-schema/reference/string#regexp)。

## 修复

`providers/schema.py` 集中转换生成用 Schema：仅移除非空白搜索正则 `\\S` 及原有本地语义注解，保留长度、类型、枚举、必填字段、对象限制和带锚点的 ID 格式。初次/修复提示词与 `response_format` 使用一致的生成 Schema。

本地权威契约不变，模型返回后仍由 Pydantic 拒绝空字符串及纯空白字符串。不会截断、补写、猜测或替换业务文字，也不把所有单字节点一律判为无效。

## 验证

- `npm run quality`：契约生成一致性、24 项后端测试、75 项前端测试、类型检查和生产构建通过。
- 新回归覆盖：整个流程图/甘特 Schema 中移除歧义 pattern、本地契约不被修改、ID 规则保留、提示词/请求 Schema 一致、本地非空白校验继续生效、搜索/完整匹配差异。
- 真实 GenerationService 流程图：使用内置合成业务流程，75.40 秒完成，8 个完整业务节点，分支含“合格”“不合格”，无修复重试。
- 真实 GenerationService 甘特图：使用合成三任务流程，15.19 秒完成，3 个完整任务名，无修复重试。
- 正式浏览器端到端：在 5174 页面点击生成，经重启后加载修复的 8010 后端与真实模型，36.1 秒完成，8 个完整节点；从页面下载了 2480 × 3508 PNG，人工查看文字和标签正常，浏览器无报错。完整模型输入输出、生成图片和密钥不纳入 Git。

已有错误版本的 JSON 不会被自动改写，需要重新生成；重新布局无法恢复已丢失的业务文字。

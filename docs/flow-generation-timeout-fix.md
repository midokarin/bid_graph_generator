# 复杂流程图生成超时修复

## 根因

2026-09-11 检查用户当前浏览器和后端任务记录：两次失败均为 `PROVIDER_TIMEOUT`，首次 JSON 为 0 字符，页面在 120.0 秒结束。失败发生在模型生成阶段，尚未进入结构校验或前端布局。

使用用户提供的材料进场报验文字、当前已配置模型和原有提示词/生成 Schema 进行一次独立测时，仅将诊断等待时限增加到 600 秒：

| 事件 | 从请求开始计算 |
| --- | --- |
| 接口返回 HTTP 200，并开始发送包含推理字段的事件 | 0.98 秒 |
| 首个非空 JSON 正文 | 145.87 秒 |
| 完整响应结束 | 164.43 秒 |

返回的 19 个节点、19 条连线通过原有 Pydantic 结构校验；同一结果在 DOWN/RIGHT 两个方向通过 ELK 布局和前端完整项目快照校验。该结果说明旧版 120 秒总时限不足以等待此次真实模型完成。耗时为单次观察，不能保证未来每次耗时相同，也不代表对业务语义的完整性作出保证。

## 修改

- 默认每次生成/修复总时限由 120 秒增加为 600 秒，覆盖推理和正文输出；仍有总时限、输出大小限制和主动取消，不无限等待。
- 显式 `BIAOSHU_TIMEOUT` 可以覆盖已有配置文件中的旧时限，不再因为已有模型配置而忽略该启动参数；不改写文件中的凭据和其他选项。
- 超时错误明确显示本次时限和模型可能仍在推理/输出，不再只提示检查配置。
- 本次同时将用户本机已有配置的时限设为 600 秒，并重启原端口的后端，确保实际页面使用修复。已有配置不会被代码静默迁移；其他旧安装可设置 `BIAOSHU_TIMEOUT=600` 后重启后端。

未修改图表契约、节点上限、提示词、业务字段或工作台样式。

## 验证

- `npm run quality` 通过：后端 26 项测试、前端 76 项测试、契约一致性、类型检查和生产构建。
- 回归覆盖旧配置的时限覆盖、凭据保留、文件不被意外重写、超限值拒绝；超时仍取消供应商请求、不创建结果，并显示实际等待时限。
- 真实模型测时和两个方向的布局校验如上；完整输入输出及本机配置不提交 Git。
- 真实 Chrome 原页面使用同一业务文字重新生成：141.1 秒收到并校验 17 个节点、17 条连线，141.3 秒完成布局与预览，创建 v2 完整版本快照；界面显示“预览已生成，可继续编辑”，截图人工查看确认画布已有新图。本次未执行导出或文件保存重开验收。

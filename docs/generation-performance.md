# 图表生成耗时调查与第一轮改进

## 结论

2026-09-11 检查用户页面上的 350.6 秒甘特图任务：0.1 秒进入模型生成，350.6 秒收到完整结果；随后校验、排期和预览均在页面计时 350.6 秒完成，没有修复回合。旧日志没有首段输出或推理计时，不能追溯这次请求内部的精确分配。

本轮真实对照确认，当前模型请求中的推理是主要耗时。精简输出明显减少了 JSON 输出阶段的时间，但尚未证明总生成耗时稳定下降。关闭思考很快，却丢失任务、改变排期，因此不启用。

## 保留的改进

- 提示模型采用简短唯一 ID、紧凑 JSON，保留完整任务文字、依赖和真正需要的补充说明。已有项目文件和模型返回内容不做静默重写。
- 明确起止日期的确定性换算不再被当成缺失工期估算，避免重复输出“请确认原文已经给出的日期”。
- 给甘特模型提供本地计算的中文日期区间参考，包括日期差和包含两端当天的天数。原始输入完整保留；不确定年份、非法日期、隐含跨年不生成参考；任务、里程碑、依赖与是否包含首尾日仍按原文判断。
- 对同一配置中明确返回“不支持 response_format”的接口记住兼容结果，避免每次生成重复发出必然失败的探测请求。只有明确不支持才缓存，修改设置后重新探测；不放宽本地校验。本轮接口支持原生 Schema，因此此项没有计入实测提速。
- 状态事件增加后端经过时间；临时日志记录各轮首段 JSON 等待、模型总耗时、输出字符数、校验和排期耗时。失败/取消同样留下已发生的模型耗时。日志只接受白名单数值，不记录原文、输出、推理文本或密钥。

模型、思考设置、Schema、本地严格校验、两次修复上限、前端布局和导出保持原有配置与规则。

## 真实实验

用户授权最多四次对照，使用当前保存的 qwen3.8-flash 配置和仓库 `docs/图表生成业务测试文本.md` 中的“政务档案管理平台实施与上线计划”。逐次执行，无并行压力；每次只生成一次，不用修复掩盖初次质量问题。完整响应仅保存在系统临时目录，没有纳入 Git。

| 实验 | 首段 JSON 等待 | JSON 输出阶段 | 模型总耗时 | 输出字符 | 结果 |
| --- | ---: | ---: | ---: | ---: | --- |
| 原提示词基线 | 172.69 s | 32.01 s | 204.70 s | 5,477 | 13 项任务/里程碑，15 条依赖，61 天 |
| 仅精简表示及澄清补充信息 | — | — | 超过 300 s 后主动取消 | — | 未完成，不计为成功样本 |
| 精简表示、澄清补充信息及日期参考 | 200.74 s | 9.21 s | 209.95 s | 2,200 | 13 项任务/里程碑，15 条依赖，61 天 |
| 同上，额外关闭思考，仅诊断 | 3.18 s | 9.48 s | 12.66 s | 2,093 | 遗漏生产切换，后续排期提前一天；拒绝采用 |

基线约 0.98 秒开始收到推理事件，计数 26,271 个推理字符；日期参考实验约 1.81 秒开始收到推理事件，计数 31,892 个推理字符。这里是字符数，不是 token 数；首段 JSON 等待也包含网络、服务端调度等开销，不能全部精确归为推理计算。关闭思考实验没有收到推理字符。

在完成的两个保持思考设置的样本中，输出字符减少约 60%，JSON 输出阶段减少约 71%，但总耗时从 204.70 秒到 209.95 秒，没有下降。样本少且推理长度与服务端时延有波动，不能据此宣称平均、P95 或用户下次生成将达到某一秒数，更不能把历史 350.6 秒与任意一次较快结果直接作为提速比例。

## 质量核对与验证

对照原文逐项检查 13 个任务/里程碑的名称对应、工期、开始/结束偏移，以及 15 条应有的 FS 依赖：

- 保留思考的日期参考实验：13/13 项工期与排期匹配；15/15 条依赖匹配且 lag=0。11 项普通任务、2 个里程碑，生产切换保留，最终完成偏移 61；没有无依据的“日期估算”补充。
- 基线：13/13 项工期与排期匹配，但 3 条依赖带了原文未要求的等待量。虽然当前排期未变，这说明 Schema 通过不等于业务语义完全正确。
- 关闭思考：只有 8/13 项任务与排期核对通过；生产切换丢失，上线及后续任务发生偏移。本地 Schema 仍能通过，因此不能靠“快速生成失败后再修复”保证内容质量。
- 日期参考实验的真实模型 JSON 经真实 Python 排期、前端版本创建及 React/SVG 渲染，保留 13 个任务组、15 个依赖组与所有任务名文字行；静态 SVG 渲染约 10.18 毫秒。这不是新增浏览器或 PNG 视觉验收。
- `npm run quality` 通过：34 项后端测试、92 项前端测试、契约同步、TypeScript 检查、生产构建。新增回归覆盖日期差/闰年/跨年/非法日期、源文保留、修复不重发源文、逐轮计时、日志脱敏及兼容探测缓存。

## 后续方向

优先评估让模型直接提取原文日期、由程序统一完成日期到工期和偏移的转换，进一步减少模型承担的确定性计算；这需要专门设计生成候选契约，并以日期、并行、提前/延后、里程碑和缺失工期用例验证完整调用链。当前日期参考只是较小的辅助，尚不能证明实现了这个更彻底的职责拆分。

若要评估关闭思考或限制思考预算，应先扩大业务回归集并检查任务覆盖与依赖语义，不能只看 JSON 校验。阿里云官方文档说明了这些思考控制参数，但当前第三方兼容接口的行为仍应以实测为准：[深度思考文档](https://help.aliyun.com/en/model-studio/deep-thinking)。本次不修改用户默认思考配置。

## 复现测时

在仓库根目录运行，本地已有结果可直接重放，不调用模型：

```sh
.venv/bin/python scripts/measure_generation.py --replay /path/to/result.json
```

下面命令会使用已保存配置调用外部模型，消耗 API 额度；默认只使用仓库上述合成测试文本。`--messages-file` 可指定事先保存的基线消息快照，其中的内容会被发送，因此仅在确认内容及目的后使用。

```sh
.venv/bin/python scripts/measure_generation.py --live
.venv/bin/python scripts/measure_generation.py --live --messages-file /path/to/baseline-messages.json
```

`--live --thinking-off` 仅用于诊断，不写入配置，不能作为本轮已通过质量验收的推荐运行方式。测时脚本输出首事件、首推理事件、首段 JSON、完整耗时和字符计数；结构有效不代表业务正确，需要另行核对。临时原始结果可用于复核，不纳入项目版本或 Git。

# 多方案流程图验收

本次交付：流程图默认关闭的“多方案生成”开关；固定 3 个独立模型候选；每个候选复用本地布局优化；缩略图、放大比较、布局推荐和采用；后端全局模型并发上限为 2。

## 验证范围

- `npm run quality`：37 个后端测试、106 个前端测试、契约一致性、TypeScript 检查和生产构建通过。
- `scripts/verify-candidates.mjs`：独立替身后端上的真实 HTTP/SSE → 校验 → ELK Worker → 候选预览 → 采用 → 保存 → PNG/SVG 导出；记录在 `browser-result.json`。
- `scripts/verify-candidate-cancel.mjs`：浏览器拦截并延迟 SSE，验证单个失败不影响其他候选、生成中先查看成功方案、切换任务保留进度、取消保留已完成候选、忽略迟到响应、排队候选取消后不创建请求，以及整轮取消恢复旧图；记录在 `cancellation-result.json`。
- 既有 `verify-concurrent-tasks.mjs` 另在临时输出目录完成回归：原有同图种多任务、甘特任务、任务取消、编辑、版本恢复和手动保存通过。
- 新增单元测试直接覆盖晚到的创建响应可被取消、候选不提前写入版本、完整快照无效时拒绝候选，以及后端排队取消和释放并发名额。

macOS / Chrome 无头浏览器，设备缩放 1。桌面截图为 1440×900 和 1920×1080 的真实视口截图，移动端为宽 390 的整页截图。

- `initial-*`：默认关闭的开关，保持原工作台分区。
- `choices-*`：候选卡片、逐个采用按钮和布局推荐。
- `enlarged-*`：候选使用既有放大预览弹窗。

- `mobile-390.png`：候选竖向排列，验证页面无横向溢出。

已目视检查新增开关、卡片和预览，沿用现有配色、圆角、字体和按钮；1440 宽度下采用按钮可直接看到。此次记录覆盖新增控件，不代表重新完成整个 Demo 的像素级基线验收。

## 数据与验收边界

所有输入和输出均来自仓库合成测试夹具，未发送真实业务资料，也未调用外部模型。替身模型有意返回相同业务结构，因此截图中的三张图相似，不能作为真实模型多样性或减少交叉效果的证明。受控提示的差异、原文不变及结构修复边界由后端测试验证；真实模型候选差异尚未验收。

候选不是正式版本；只有采用的完整快照进入项目文件。采用后仍需手动保存。未采用候选只留在当前任务会话，新生成、修改输入或切换图种会清除；完成保存后不会因其余候选仍在而继续显示项目未保存。

## 复验

对独立测试端口启动明确指定 `Settings(provider="stub")` 的后端，再让 Vite 的 `BIAOSHU_API_PORT` 指向它。不能只依赖 `BIAOSHU_PROVIDER=stub` 覆盖用户已有配置；测试脚本会检查健康接口的 provider，非 stub 时拒绝运行。

```sh
npm run quality
BIAOSHU_WEB_URL=http://127.0.0.1:5192 node scripts/verify-candidates.mjs
BIAOSHU_WEB_URL=http://127.0.0.1:5192 node scripts/verify-candidate-cancel.mjs
```

如环境未安装 Playwright，可通过 `PLAYWRIGHT_MODULE` 指定已有的模块入口。浏览器测试需要已安装 Chrome。

# 标书图表生成程序：Agent 开发需求与技术决策

> 文档状态：产品与技术基线（P0）  
> 适用对象：负责规划、实现、测试和评审本项目的开发 Agent  
> 当前阶段：从交互 Demo 迁移为可独立运行的本地程序  
> 最终方向：作为大型 Web 标书生成程序中的图表插件

## 0. Agent 必读规则

本文件是当前产品需求与技术边界的主要依据。开发 Agent 开始工作前，必须先读取仓库根目录的 `AGENTS.md`、本文件、当前 Git 状态和相关源码。

本文使用以下约束词：

- **必须**：P0 不得偏离的已确认决策。
- **应该**：推荐实现方式；如需改变，必须说明依据和影响。
- **预留**：数据结构或架构要允许以后扩展，但 P0 不实现对应能力。
- **不在 P0**：不得为了“完整”而提前扩大范围。

Agent 实施时必须遵守以下原则：

1. JSON 是图表业务内容的唯一事实源；布局、样式和导出均由本地程序完成。
2. 必须区分结构校验和业务判断：结构错误必须拦截；用户明确要求不判断的业务冲突不得擅自增加阻断。
3. Demo 是前端页面外观与既有交互的强制基线，必须遵守第 8.5 节；Demo 本身不代表正式后端、数据契约或完整验收已经完成。
4. 三次开发会话按第 12 节顺序推进；每次完成合并目标、最小验证并形成 Git 提交。
5. 密钥、完整模型输入输出和本机路径不得提交到 Git。

## 1. 产品定义

### 1.1 一句话定义

这是一个面向个人使用的本地标书图表生成工具：用户粘贴业务文字，云端 AI 将其转换为严格的结构化 JSON，本地程序据此生成可修改的流程图或甘特图，并导出 PNG/SVG。

### 1.2 P0 用户与使用环境

- 第一阶段只面向单个个人用户。
- 不需要登录、账户、角色、团队空间或多人协作。
- 以本机浏览器访问本地服务的方式运行。
- 前端目标浏览器为 Chrome 和 Edge。
- 目标操作系统为 macOS、Windows 和 Linux；不得写死单一系统路径。
- 本地 API 只监听 `127.0.0.1`，不得默认开放到局域网。
- 第一版作为独立页面使用；未来可嵌入宿主 Web 程序的独立页面、侧边栏或弹窗。

### 1.3 P0 输入与输出

输入：

- 用户手工粘贴一段业务文字。
- 用户选择图表类型：流程图或甘特图。
- 流程图生成前，用户选择布局方向：从上到下或从左到右。
- P0 不提供额外的“生成要求”输入框，但接口和数据结构要允许后续增加。
- 未来宿主程序可以把用户选中文字传给插件；独立模式仍保留手工粘贴。

输出：

- 校验通过的流程图 JSON 或甘特图 JSON。
- 本地渲染的可见图表。
- PNG 文件。
- 普通 SVG 文件。
- 一段简短图表说明。
- “AI 补充”状态。

### 1.4 P0 编辑范围

允许：

- 修改节点或任务文字。
- 拖动流程图节点位置。
- 调整全局字体、颜色、线宽、圆角和背景等样式。
- 套用预设模板。
- 重新自动布局。
- 恢复历史版本。

不允许：

- 新增或删除节点。
- 新增、删除或修改流程图连线。
- 新增、删除或修改甘特图依赖。
- 通过自然语言再次修改已有图表。
- 做成接近 draw.io 的完整绘图工具。

## 2. 总体技术架构

### 2.1 技术选型

| 层级 | P0 技术 | 职责 |
|---|---|---|
| 前端 | React + TypeScript + Vite | 页面、交互、版本浏览、布局、SVG 渲染、浏览器导出 |
| 本地后端 | Python + FastAPI | 模型调用、流式任务、Schema 校验、甘特确定性排期、修复重试、配置和临时日志 |
| 数据契约 | Pydantic + JSON Schema + TypeScript 类型 | 约束项目文件、流程图和甘特图数据 |
| 流程图布局 | ELK.js，浏览器 Web Worker | 根据业务结构计算节点坐标和连线折点 |
| 图表渲染 | React/SVG | 流程图和甘特图共用可见预览与 SVG 输出 |
| P0 PNG 导出 | 浏览器 SVG → Canvas → PNG | 保证预览与导出使用同一布局结果 |
| 项目存储 | 单个本地 JSON 文件 | 保存原文、当前状态和全部版本快照 |

说明：当前 Demo 使用 Node.js，是因为 React/TypeScript 前端需要 Node 进行开发构建。它与 Python/FastAPI 后端并不冲突。浏览器运行构建后的 JavaScript，前后端通过本机 HTTP/SSE 通信。

### 2.2 必须保持的职责边界

```text
用户输入文字
  → FastAPI 组装图种专属提示词和 Schema
  → 云端模型返回 JSON 字符流
  → 后端累积完整响应
  → 去除代码围栏/首尾空白
  → Pydantic 严格校验
  → 必要时让模型修复，最多两次
  → 甘特图由后端确定性排期器计算时间，流程图跳过此步
  → 返回校验通过的业务 JSON和甘特派生排期
  → 流程图由前端 ELK.js 计算布局
  → 保存完整版本快照
  → React/SVG 渲染
  → PNG/SVG 导出
```

禁止的替代路径：

- LLM → Mermaid → 直接作为项目事实源。
- LLM → Python/Matplotlib 代码 → 本机执行。
- LLM → SVG/HTML → 直接插入页面。
- 前端和后端分别独立布局同一张图。

Mermaid 或 Matplotlib 以后可以作为受程序控制的内部渲染器或测试工具，但不能接收和执行模型自由生成的代码。

### 2.3 推荐代码分层

具体目录名可以结合现有仓库调整，但依赖方向必须保持清晰：

```text
backend/
  app/domain/        # Pydantic 契约、纯业务校验、甘特排期、任务状态
  app/providers/     # OpenAI 兼容模型适配器
  app/services/      # 生成、校验、修复、取消
  app/api/           # FastAPI 路由、SSE
  app/settings/      # 本机配置与密钥读取

frontend/
  src/domain/        # 生成后的 TS 契约与项目模型
  src/api/           # 本地后端客户端和 SSE 客户端
  src/layout/        # ELK 适配器、Web Worker、已有布局读取
  src/renderers/     # Flowchart SVG、Gantt SVG
  src/editor/        # 文字、位置、样式编辑
  src/project/       # 打开、保存、另存为、版本历史
  src/adapters/      # 独立运行/未来宿主适配边界

packages/contracts/  # 导出的 JSON Schema、共享示例与契约测试数据
```

领域服务不得依赖 FastAPI 请求对象，以便未来作为 Python 包或路由模块加入大型宿主程序。

## 3. 数据契约

### 3.1 总原则

- 流程图和甘特图必须使用两套独立 Schema。
- 项目文件可以通过 `diagram_type` 选择对应 Schema，但不能强行让两种图共享业务字段。
- 核心字段必须严格校验，未知字段必须拒绝。
- 只允许在明确的 `metadata` 扩展区保留未来扩展数据。
- 业务内容、布局数据和样式数据必须分开保存。
- 每次修改保存完整快照，不使用 Patch 作为 P0 持久化格式。
- 项目文件版本与图表 Schema 版本必须分别记录。
- P0 不记录每个节点对应的原文片段或字符位置。

### 3.2 项目文件建议结构

以下结构是落实已确认决策的推荐契约，字段命名可在首次契约任务中微调，但语义不得丢失：

```json
{
  "project_file_version": "1.0",
  "diagram_type": "flowchart",
  "source_text": "用户粘贴的原始文字",
  "current_revision": 2,
  "versions": [
    {
      "revision": 1,
      "created_at": "ISO-8601 时间",
      "origin": "ai",
      "spec": {},
      "layout": {},
      "style": {},
      "supplements": [],
      "summary": "图表简短说明"
    }
  ],
  "metadata": {}
}
```

P0 一个项目文件只包含一张图及其所有版本。多图项目属于后续升级范围。

### 3.3 AI 补充数据

当原文缺少信息而模型进行了合理补充时，模型必须逐项记录：

```json
{
  "target_type": "task",
  "target_id": "task-3",
  "reason": "原文未提供该任务工期",
  "question": "请确认预计工期是否为 5 天"
}
```

要求：

- 数据层逐项保存补充对象、原因和待确认问题。
- P0 界面只显示整张图的“AI 补充”标志，不要求逐项确认。
- AI 补充不阻止导出。
- 原文未给出甘特任务工期时，AI 可以估算，但必须记录为补充。

## 4. 流程图规格

### 4.1 节点类型

P0 固定支持以下六种类型：

| 类型 | 建议枚举 | 图形 | 语义 |
|---|---|---|---|
| 开始 | `start` | 圆角终止框 | 流程入口 |
| 结束 | `end` | 圆角终止框 | 流程终点 |
| 普通步骤 | `process` | 矩形 | 实施、审核、培训等动作 |
| 判断 | `decision` | 菱形 | 真正会改变后续路径的条件判断 |
| 文档/成果物 | `document` | 文档形 | 方案、报告、清单、交付资料 |
| 子流程 | `subprocess` | 双边矩形 | 暂不展开的复杂流程 |

“审核”“审批”如果只是顺序动作，应使用 `process`；只有存在通过/驳回等分支时才使用 `decision`。

### 4.2 节点与连线字段

流程图业务 JSON 至少应表达：

- 稳定且唯一的节点 ID。
- 节点类型和文字。
- AI 建议层级。
- 可选责任主体和阶段。
- 稳定且唯一的连线 ID。
- 连线起点、终点和可选分支文字。
- 普通连线或整改回路标记。

责任主体和阶段只在 JSON 中预留；P0 不渲染泳道或阶段背景。

### 4.3 图结构约束

- 单张流程图最多 20 个节点。
- 一个节点可以有多个后续分支。
- 分支连线可以带任意简短业务标签，不限于“是/否”。
- 允许“检查不合格 → 整改 → 返回检查”等回路。
- AI 必须把此类返回关系标记为整改回路。
- 连线两端必须引用存在的节点。
- 节点和连线 ID 不得重复。
- P0 用户不能编辑连线。

### 4.4 布局

- 用户生成前选择 `DOWN` 或 `RIGHT`，用户选择是最终权威值。
- AI 可以在响应中回显方向并提供节点层级意图，但不得覆盖用户选择，也不提供精确像素坐标。
- ELK.js 在浏览器 Web Worker 中运行。
- 推荐使用 ELK Layered 和正交连线。
- ELK 计算节点坐标以及连线折点，两者必须保存到版本快照。
- 用户拖动节点后，切换样式不得改变节点位置。
- 只有用户点击“重新布局”时才再次执行 ELK。
- 打开已保存项目时优先使用快照中的坐标和折点，不自动重排。

### 4.5 长文字

- 节点文字应自动换行。
- 超过可读范围时，程序应提示用户精简，不得无限缩小字号。
- 具体字符数和行数上限尚未由产品确认；实现时必须集中为可测试常量，不得散落硬编码。

## 5. 甘特图规格

### 5.1 AI 输出与本地计算

AI 输出：

- 图题。
- 时间单位。
- 任务 ID、任务名称和工期。
- 任务依赖。
- 可选最早开始位置。
- 依赖的提前量或延迟量。
- 多个里程碑。
- AI 补充信息。

Python 领域层的确定性排期器计算：

- 每个任务的确定性开始和结束位置。
- 并行任务位置。
- 里程碑位置。

前端根据派生排期计算画布尺寸和行位置，并通过 React/SVG 渲染。

### 5.2 时间单位

P0 允许 AI 从受控枚举中选择：

- `calendar_day`
- `week`
- `month`

不允许 AI 返回任意单位字符串。一张甘特图只能使用一个时间单位。

“工作日”在数据结构中可以预留，但 P0 不支持工作日日历、不排除周末，也不配置法定节假日。

### 5.3 排期规则

- 允许任务并行。
- P0 依赖类型为“前置任务完成后，后置任务开始”。
- 依赖允许携带提前量或延迟量；负数表示提前，正数表示延迟。
- 任务可以设置“最早从第 N 个时间单位开始”。
- 支持多个零工期里程碑。
- 依赖不得形成循环；循环依赖必须进入 AI 修复流程，不能由程序擅自删除依赖。
- 如果两次修复后仍然成环，则生成失败。
- 原文总工期与计算结果冲突时，P0 直接生成，不警告、不阻止导出，也不自动缩短任务。
- P0 不对排期合理性作业务判断，只保证结构有效且算法能够完成计算。

### 5.4 画布

- 甘特图使用 React/SVG 绘制。
- 任务较多时，画布纵向增长并输出长图。
- P0 不自动分页或拆成多张图。
- P0 用户只能修改任务文字，不能修改工期、依赖或时间条位置。

## 6. AI 生成系统

### 6.1 供应商配置

- 使用可配置的 OpenAI 兼容接口。
- 用户可在设置页面填写 API Key、接口地址和模型名。
- P0 不开放 temperature 等全部模型参数给用户。
- 独立运行时由图表程序管理配置；嵌入宿主后可改由宿主提供模型配置。
- 优先使用供应商原生 JSON Schema/结构化输出能力；供应商不支持时，退回提示词约束 JSON。

### 6.2 提示词

- 流程图和甘特图使用两套独立提示词和独立 Schema。
- P0 用户不能编辑系统提示词。
- P0 没有“额外生成要求”输入框，但服务方法应预留可选字段，默认值为空。
- 模型只返回最终结构，不要求返回完整思维过程。
- 正常输出包括图表 JSON、逐项 AI 补充信息和简短说明。

### 6.3 解析、校验和修复

本地安全清理只允许：

- 去除首尾空白。
- 去除包裹 JSON 的 Markdown 代码围栏。

不得静默修改业务字段、删除未知字段、重写依赖或补造节点。

处理顺序：

1. 累积模型完整响应。
2. 执行有限包装清理。
3. 根据选定图种执行严格 Pydantic 校验。
4. 校验失败时，把错误 JSON 和结构化校验错误发送给模型修复，不重复发送原始输入。
5. 最多自动修复两次。
6. 仍失败时，显示通俗错误，并允许用户展开技术详情。

必须校验的技术问题至少包括：

- 字段类型与必填字段。
- 未知核心字段。
- 枚举值。
- 唯一 ID。
- 引用完整性。
- 流程图最大节点数。
- 甘特任务依赖环。
- 布局和渲染所需的基本数值范围。

不得增加的 P0 业务阻断包括：

- 总工期是否满足标书要求。
- AI 补充内容是否得到用户逐项确认。
- 配色是否符合实际招标文件。
- 图表内容是否完整覆盖真实项目要求。

## 7. 生成任务与 SSE

### 7.1 通信方式

P0 使用“创建任务 + SSE 事件流”：

```text
POST   /api/v1/generations
GET    /api/v1/generations/{job_id}/events
DELETE /api/v1/generations/{job_id}
```

路径可以在 API 任务中调整，但必须保留对应语义：创建、订阅事件、取消。

建议任务状态：

```text
queued
→ generating
→ validating
→ repairing（0～2 次）
→ completed

或 → cancelled / failed
```

### 7.2 前端反馈

- 首次打开时图表预览画布保持空白，不显示示例图。
- 生成新图表时，画布显示加载动画和“正在生成”；成功后展示新图。重新生成时暂时隐藏旧图，取消或失败后恢复已有图表，不创建新版本。
- 显示“正在理解内容、正在生成结构、正在校验、正在修复、正在布局”等阶段状态。
- 在一个较小窗口中流式显示模型输出的 JSON 文本。
- 默认折叠各次修复记录，用户可以展开查看首次生成和每次修复的输出。
- 流式 JSON 只用于观察，不能在响应完成前驱动正式画布。
- 只有完整响应解析和校验通过后，才能进入布局与创建版本。

### 7.3 并发、取消与重新生成

- 同一页面允许多个独立工作台任务；每个工作台同一时间只运行一轮生成。流程图可开启“多方案生成”，一轮生成 3 个候选；后端同时最多执行 2 个模型生成任务，其余排队。
- 用户取消后，后端应尽量真正取消供应商请求。
- 如果供应商不支持真正取消，则必须忽略迟到响应。
- 取消任务不保存失败草稿、不创建图表版本。
- 已有图表时点击“重新生成”，必须先弹窗确认。
- 单方案生成成功后创建新版本，保留旧版本；多方案生成只有用户选择采用后才创建版本。

### 7.4 多方案流程图（2026-09-11 用户确认）

- 在生成按钮旁提供“多方案生成”开关，默认关闭；仅流程图显示，开启后固定生成 3 个候选。
- 同一份业务文字、图题、布局方向和初始样式用于全部候选。后端根据受控枚举分别添加“主流程优先”“分支清晰”“阶段层次”提示；不允许为美观删减业务步骤、改变依赖或遗漏分支及整改回路。
- 每份结构独立校验和修复，再复用现有本地布局优化。生成偏好只作用于首次提示，修复只修结构、不重新组织业务。用户方向始终优先。
- 每个候选独立显示进度、失败原因、生成详情和缩略图；先完成的可先放大。单个失败不影响其他候选。
- 正在运行时可取消剩余生成；保留已经完成的候选。取消中的或排队中的候选不得产生版本，迟到结果必须忽略。整轮取消且没有候选完成时恢复原图。
- 生成结束或取消剩余生成后，点击“采用此方案”才追加完整正式版本；只浏览候选不创建版本。之后可重新比较并采用另一个方案，保留前一版本。
- 候选只在所属任务的本次会话中暂存，切换工作台任务不丢失；新一轮生成、切换图种或修改生成输入会清除旧候选。项目文件只保存已采用版本及后续编辑，不保存未采用候选。
- 至少两个候选有效且整轮结束后，按现有布局指标给出“布局推荐”；该标记不代表业务正确性。提示词不能保证明显不同或零交叉。
- 开关开启时提示调用模型 3 次、增加模型用量；结构修复仍沿用既有限额，可能发生额外调用。甘特图继续单方案生成。

## 8. 渲染、样式与导出

### 8.1 渲染原则

- 流程图和甘特图都使用 React/SVG。
- P0 不引入 Mermaid 作为渲染事实源。
- 预览和导出必须使用同一个已保存布局快照。
- SVG 是普通展示文件，不内嵌项目 JSON、原始输入或模型响应。

### 8.2 样式

P0 提供：

- 固定样式模板。
- 全局字体。
- 文字颜色。
- 线条颜色和线宽。
- 节点填充色。
- 画布背景色。
- 透明背景。
- 节点圆角等全局参数。

P0 不提供单节点独立样式和自定义模板保存。

业务数据与样式必须作为快照中的不同字段。切换模板不能改变节点、连线、工期、依赖或用户位置。

### 8.3 图片导出

- 按完整图表自身尺寸导出，不提供纸型或纸张方向设置，不套入纸张、不增加纸张留白。
- PNG 按图表布局尺寸的 3 倍分辨率导出；保留图题和背景选项，长图不分页。
- 支持 PNG 和普通 SVG。
- 导出时由用户选择是否把图题写入图片。
- 图题不应成为业务图形结构的一部分。
- P0 PNG 在浏览器中由 SVG 转换为 Canvas 后导出。
- 正式嵌入宿主前，再评估是否改为独立浏览器渲染服务。

### 8.4 字体

- 开发阶段使用系统字体和回退字体。
- UI 可以允许用户选择可用的本机字体。
- 内置字体、字体授权、包体积和跨平台一致性在正式宿主集成前决定。
- 在字体方案确定前，不得宣称跨平台像素级一致。

### 8.5 前端严格沿用 Demo

**基线版本**：以提交 `2c473bfb7334b8bccee8b36a886cbe186318f6a7` 中的 `demo/` 为准（包含可选择的版本历史）。后续只有用户明确认可的界面改动才能更新基线；Agent 不得修改 Demo 或更新基准截图来掩盖正式页面偏差。

**复用要求**：正式前端必须沿用 Demo 的页面组件、CSS 和视觉资源；允许为了真实数据接入拆分组件、调整状态管理，但不得自行重做页面设计。必须保持导航栏、顶部操作区、三步流程、输入区、预览区、模板区的排列与比例，以及字号、间距、配色、边框、圆角、阴影、图标、按钮和弹窗样式。既有版式设置、版本历史选择与恢复、文字编辑和拖动等交互按基线保留，并服从本文明确的 P0 功能边界。

**允许变化**：真实数据、生成状态、文件保存方式以及“演示”等失实文案可按已确认需求替换。模型设置、JSON 流窗口和新增导出选项必须使用既有样式，以局部控件或弹窗接入；未经用户确认，不得改变主要页面分区、操作入口位置或整体视觉风格。需求与基线冲突时须列明具体冲突，不能自行以“优化体验”为由改版。

**画布边界**：页面外观与图表业务布局分开验收。真实节点数量、文字、甘特时间和 ELK 坐标允许随输入变化；节点形状、文字风格、线条和模板视觉必须延续 Demo。不得要求真实图表复制固定示例坐标，也不得用自动布局作为改变工作台外观的理由。

**一次集中视觉验收**：会话二实现前记录基线截图，会话二完成时进行对照；会话三只复核新增控件和导出弹窗。固定同一操作系统、浏览器版本、已加载字体、100% 浏览器缩放、设备像素比和示例数据，至少使用 1440×900 与 1920×1080 两个视口。覆盖流程图/甘特图主工作台、版式设置、版本记录和导出弹窗。

交付一份简短对照记录即可，包含基线提交、运行环境、前后截图及差异说明。无授权差异的页面区域必须无肉眼可见的布局或样式偏差；文本抗锯齿微差可以解释后排除。画布动态布局和已确认新增控件单独列出，不得遮盖整块页面来规避对比。发现偏差应修复后复核；功能测试通过不代表视觉验收通过。未取得真实截图不得声明严格还原完成。

## 9. 项目文件、版本和未保存状态

### 9.1 保存策略

- 一个项目保存为一个可读 JSON 文件。
- 项目文件保存原始输入文字和全部完整版本快照。
- 第一次保存时打开系统文件选择窗口。
- 后续“保存”默认覆盖原文件，同时提供“另存为”。
- 目标浏览器为 Chrome/Edge；文件访问能力应封装为适配器，并准备普通上传/下载回退方案。
- P0 不使用 SQLite、服务器数据库或浏览器 localStorage 作为正式项目存储。

### 9.2 不使用自动恢复副本

最终决策：P0 不自动保存、不维护恢复副本，也不在 IndexedDB 或后端目录中保存项目副本。

因此必须实现：

- 明确的“已保存/有未保存修改”状态。
- 页面关闭或打开其他项目之前的未保存提示。
- 保存成功后才把当前版本标记为已保存。
- 保存失败不得清除脏状态。

程序异常或用户强制关闭时，未保存内容可能丢失，这是已接受的 P0 边界。

### 9.3 版本

- AI 首次生成创建 v1。
- 文字、位置、样式、模板和重新布局等已应用修改均创建完整新快照。
- 检查、缩放、打开弹窗等纯 UI 行为不创建版本。
- 恢复旧版本时创建一个内容等于旧版本的新版本，不倒退或重用版本号。
- 每个版本保存业务 JSON、布局、样式、AI 补充信息和简短说明。

### 9.4 文件兼容性

- 打开旧版项目文件时，程序执行显式迁移。
- 迁移成功后提示用户重新保存。
- 不得静默覆盖原文件。
- 如果文件来自更新版本且当前程序无法理解，应拒绝打开，并显示所需程序版本。
- 不得通过忽略未知核心字段来猜测性降级。

## 10. 配置、密钥和日志

### 10.1 模型配置

- 设置页面提供 API Key、Base URL 和模型名。
- 配置以明文保存在用户配置目录，不写入图表项目文件。
- 配置目录必须根据 macOS、Windows、Linux 采用平台安全路径，不得写死开发者目录。
- 配置文件不得进入 Git。
- UI 显示 Key 时应遮盖大部分字符。
- 后端和日志不得打印完整 API Key 或认证请求头。

明文密钥是用户接受的个人本地版取舍；未来宿主集成可改由宿主统一提供模型配置。

### 10.2 临时调试日志

- 运行期间允许记录完整用户输入、模型输出和错误，服务于个人本地调试。
- 日志不得记录完整 API Key 或认证头。
- 日志只写入系统临时目录。
- 程序正常退出时删除本次完整调试日志。
- 程序启动时清理上次异常退出遗留的同类临时日志。
- 日志不得进入项目 JSON 或 Git。

## 11. 宿主插件适配边界

### 11.1 已知方向

- 最终宿主是正在开发的大型 Web 标书生成程序。
- P0 先做独立页面。
- 后续同时支持独立页面、侧边栏或弹窗。

- 插件向宿主返回：图表 JSON、PNG/SVG 和简短说明。

## 12. 三次开发会话计划

P0 开发压缩为下面三次连续会话。一次“会话”代表一个可独立委托给 Agent 的合并任务，不代表只能产生一次代码提交。每次会话开始时必须检查 `AGENTS.md`、本文件、Git 状态和上一次交付；结束时必须完成本会话的最小检验并提交 Git。

检验遵循“少而关键”：优先用一条统一质量命令、两图种代表样例和完整用户路径证明结果，不为每个内部模块重复制作交付材料。自动测试、替身模型、真实模型和浏览器证据必须如实区分。

### 会话一：正式骨架、数据契约与生成后端

**目标**：把 Demo 升级为可启动的前后端工程，使后端能够通过统一模型接口产出严格、可消费的两类图表 JSON。

**合并交付**：

1. 建立正式前后端目录、启动入口、统一质量命令和安全 `.gitignore`，保留第 8.5 节指定 Demo 作为前端强制视觉基线。
2. 完成项目文件、FlowchartSpec、GanttSpec、样式、布局、AI 补充和版本快照契约：以 Pydantic 为权威，导出 JSON Schema 和 TypeScript 类型，并提供两图种样例与迁移入口。
3. 完成可配置 OpenAI 兼容适配器、两套提示词、任务/SSE/取消、有限 JSON 清理、严格校验、最多两次修复、错误详情和临时日志；先用可控替身验证任务状态。

**最小检验**：

- 一条质量命令通过后端测试、前端类型检查和构建。
- 流程图、甘特图各一个样例能被 Python 与 TypeScript 一致接受；缺字段、悬空引用和甘特依赖环能被拒绝。
- 一个 API 测试覆盖 SSE 成功、一次修复成功和取消后不产出结果。

**结束条件**：前后端可启动，替身模型能从创建任务走到“已校验 JSON”，契约和测试已提交。此时不要求正式画布或真实模型验收。

### 会话二：双图渲染、工作台编辑与版本链路

**目标**：把已校验 JSON 变成可见、可修改、可追溯的流程图和甘特图，形成核心工作台。

必须按第 8.5 节复用 Demo 页面组件与 CSS，在实现前记录基线截图；不得重新设计工作台。

**合并交付**：

1. 前端接入 SSE 阶段状态与可展开 JSON 流窗口；流程图通过 ELK.js Web Worker 完成 DOWN/RIGHT 布局、六类节点、多分支、整改回路、拖动和重新布局，并保存节点坐标与连线折点。
2. Python 领域层完成日/周/月、依赖提前/延迟、最早开始、并行任务、多里程碑和环检测的确定性甘特排期；前端用 React/SVG 绘制可纵向增长的甘特图。
3. 在同一工作台完成文字编辑、全局样式、模板、AI 补充标志、完整快照版本、历史查看和恢复；不提前实现节点/连线增删、依赖编辑或自然语言二次修改。

**最小检验**：

- 流程图和甘特图各一个样例完成“JSON → 布局/排期 → SVG”测试。
- 相同输入得到相同排期；保存的流程布局重新加载后坐标与折点不变。
- 一条浏览器主路径完成生成、编辑、创建新版本和恢复旧版本，同时完成第 8.5 节截图对照，页面无未经确认的视觉偏差；前端测试与构建通过。

**结束条件**：使用替身模型时，两种图都能在正式工作台生成、编辑并保存内存版本，核心视觉与交互可实际操作并已提交。此时不要求项目文件和正式导出闭环。

### 会话三：文件与导出闭环、真实模型和集成准备

**目标**：补齐个人本地程序的交付能力，并以真实模型和真实浏览器完成 P0 总验收。

**合并交付**：

1. 完成打开、保存、覆盖、另存为、旧版迁移、未来版本拒绝和未保存提示；不增加自动保存或恢复副本。
2. 完成 A4/A3、横竖向、是否包含图题、白色/透明/自定义背景，以及与预览同源的 PNG/SVG 导出。
3. 完成设置页、用户配置目录中的模型配置、`127.0.0.1` 限制、临时日志清理、跨平台路径适配和独立模式 host adapter；不绑定尚未稳定的宿主协议。
4. 使用实际配置的 OpenAI 兼容模型分别生成一张流程图和一张甘特图，在真实 Chrome 或 Edge 中完成生成、编辑、导出、保存和重开。

**最小检验**：

- 一条统一质量命令全部通过。
- 两张真实模型图完成“生成 → 编辑 → PNG/SVG → 保存 → 关闭 → 重开”闭环。
- 复核新增设置、JSON 流窗口及导出弹窗沿用 Demo 样式，记录第 8.5 节要求的前后截图与允许差异。
- 验证取消不创建版本、保存失败不清除未保存状态、未来版本文件被拒绝、服务只监听回环地址；其他边界由已有自动测试覆盖。

**结束条件**：第 13 节主场景和关键错误边界均有对应证据，工作区已提交且没有密钥或完整临时日志被纳入 Git。只有真实模型和浏览器闭环成功时才可声明 P0 完成；当前机器无法验证的操作系统、浏览器或外部条件必须标为未验证，不能用替身结果代替。

## 13. P0 完整验收场景

至少使用以下真实交互场景验收，不能只依靠静态 Schema 测试：

### 13.1 流程图

1. 用户粘贴包含实施、检查、整改和验收回路的文字。
2. 选择从上到下布局并生成。
3. 小窗口显示 JSON 流和阶段状态。
4. 后端返回包含六类节点中相关类型、多分支和整改回路的有效 JSON。
5. 前端通过 ELK 生成节点坐标和正交连线。
6. 用户修改节点文字、拖动节点、应用模板。
7. 每次确认修改后创建新版本。
8. 用户选择是否包含图题，导出 PNG 和 SVG。
9. 保存项目，关闭后重新打开，布局和版本历史不变。

### 13.2 甘特图

1. 用户粘贴包含并行任务、依赖、延迟、里程碑和缺失工期的文字。
2. AI 返回受控时间单位、任务、依赖和逐项补充信息。
3. 本地排期器确定性计算任务时间。
4. 界面显示整图“AI 补充”标志，但允许直接导出。
5. 用户修改任务文字和全局样式。
6. 长图随任务数量纵向增长。
7. PNG/SVG 与当前预览使用相同数据。

### 13.3 错误与边界

- 模型返回 Markdown 代码围栏包裹的 JSON：本地清理后成功。
- 模型返回缺字段或未知核心字段：进入修复。
- 连线引用不存在节点：进入修复。
- 甘特依赖成环：进入修复，程序不得自行删边。
- 两次修复仍失败：显示通俗错误和可展开详情，不创建版本。
- 用户取消：不创建版本；迟到响应被忽略。
- 保存失败：仍显示未保存状态。
- 打开未来版本项目：拒绝并说明版本要求。
- 关闭含未保存修改的页面：出现明确提示。

# 本地服务连接修复

2026-09-12：生成报“本地服务返回 500”，模型设置保存报 JSON 解析错误。

## 原因与修复

- 现场前端 `/api/v1/health` 返回空内容 HTTP 500，后端端口 8000 拒绝连接；启动后端后，同一前端代理恢复 HTTP 200。
- 模型设置保存失败时直接调用 `response.json()`，空响应导致解析异常。设置与生成现在共用响应处理，服务故障提示启动后端和检查端口；空内容和非 JSON 响应均显示可读错误。
- 新增 `npm start`：检查端口、启动后端并等待健康检查，再启动前端；退出时清理本次启动的配套服务。已有服务占用端口时明确提示，不接管或终止其他进程。
- 保留 `npm run backend` 和 `npm run dev` 分别启动的开发方式，README 明确仅启动前端不足以生成或保存模型设置。

## 验证

- `npm run quality` 通过，包含后端测试、121 个前端测试、契约检查、类型检查和生产构建。
- 新增客户端回归覆盖生成/读取设置/保存设置的空 500，以及空/HTML 成功响应、设置冲突和正常配置响应。
- 浏览器现场读取原有模型配置并原样保存，页面显示“模型配置已保存”。
- 使用独立端口验证 `npm start`、前端代理健康检查、重复启动的端口冲突提示和退出后的服务清理。
- 未调用外部模型；生成正确性证据为本地替身测试，不代表真实模型生成验收。

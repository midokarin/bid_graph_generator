# 多任务并发生成交付

## 使用方式

- 左侧新增「会话任务」，点击「新建任务」创建独立的空白任务；点击任务名称切换。
- 在任务 A 开始生成后，可新建任务 B、输入另一份内容并生成；流程图与甘特图都支持，同类图表也可以并发。
- 列表显示生成中、已完成、失败、取消状态和未保存标记。任务名称使用输入图题，未填写时显示任务序号。
- 各任务独立保留输入、预览、运行日志、取消控制器、编辑草稿、版式、文件句柄及版本记录。后台结果进入发起它的任务；取消只影响当前任务。
- 「版本记录」显示当前任务、当前图种的版本；恢复、重新生成和修改都只新增本任务的版本。
- 保存项目只保存当前任务、当前图种。仍采用原有单图项目文件，不自动保存或持久化整个任务列表；刷新或关闭前需逐个保存，未保存或仍在运行时会触发浏览器离开提醒。

## 实现边界

后端原有 `asyncio.create_task` 已按生成请求并发执行。本次通过独立工作台实例与独立 Zustand store 消除前端单任务限制，无需新建 Python 线程池。切换时保留组件和运行连接，隐藏非当前工作台；输入与运行详情使用独立控件 ID。

同一任务内仍需等待本次生成完成或取消后再生成。并发不会缩短单次模型响应时间；实际模型接口的并发与限流能力由提供方决定。

保留原有主页面、输入、预览和模板区，扩展左侧栏；窄屏将任务列表改为横向滚动。未修改用户已有的规格调整；同时进行的图题编辑改动不纳入本次提交。

## 验证

对仅包含本次改动的独立副本执行：

- `npm run quality`：后端 35 项、前端 93 项测试全部通过，契约同步检查、TypeScript 检查和生产构建通过。
- 后端并发回归：两个慢请求在任一完成前都进入模型生成；取消第一个不阻止第二个产出完整结果，取消任务没有结果。
- Chrome 浏览器回归：两份流程图和一份甘特图同时生成；交错完成、取消后的迟到响应、后台重试、按任务查看与恢复版本、分别保存文件、版式草稿切换保留均通过。
- 保存文件核对：甘特任务保存 1 版，另一个流程任务保存 3 版；原文、图题及版本未混入其他任务。
- 1440×900、1920×1080 与 390×844 截图检查；移动端可新建和切换任务，无页面横向溢出、重复控件 ID或浏览器异常。

浏览器通过拦截 SSE 返回可控慢响应，后端测试采用本地替身；本次没有调用真实外部模型，不将以上结果表述为真实模型并发性能验收。

证据位于 `docs/evidence/concurrent-tasks/`，包括改动前截图、并发及完成状态、当前任务版本记录、手机界面、浏览器检查结果和质量输出。

复验入口：`scripts/verify-concurrent-tasks.mjs`，通过 `BIAOSHU_WEB_URL` 指定前端地址、`PLAYWRIGHT_MODULE` 指定已安装的 Playwright 模块路径。

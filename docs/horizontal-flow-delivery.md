# 横向流程图可读性调整

## 改动

- RIGHT 普通节点与判断节点按文字长度确定宽度，长文字使用较短行，避免沿用纵向的统一宽节点。
- 单主线、直接整改回路的图采用水平对齐布局；整改节点位于判断下方，去程与返回路径分开，预留标签空间。
- 多分支等其他拓扑继续使用 ELK，复用紧凑节点尺寸。
- 渲染和可读性检查共用换行规则；已有宽节点快照保持原来的十二字换行。打开项目不自动重新布局，用户可通过“重新布局”应用新几何。
- 工作台外观、业务结构、导出纸型与配色不变。

## 验证

- `npm run quality` 通过；随后补充旧快照换行测试并通过前端 78 项测试、类型检查与构建。
- 合成“项目实施与验收流程”样例：主线水平对齐，整改节点下置，所有连线正交，普通节点没有被连线穿过；长文字可读性检查通过。
- 多分支 DOWN/RIGHT 均通过真实 ELK 布局测试，原有纵向布局与导出测试通过。
- agent-browser/Chromium 在 1440×900、1920×1080 下检查正式 Diagram 组件的独立渲染，截图见 [1440](evidence/horizontal-flow/1440.png)、[1920](evidence/horizontal-flow/1920.png)。外围标题和白底容器是检查页，截图不是完整工作台验收。
- 正式 ExportSheet 输出 A4 横向 SVG，并在浏览器通过 SVG → Canvas → PNG 转换，尺寸为 3508×2480。
- 本次使用仓库合成样例验证本地布局与渲染，没有调用外部模型，也不代表真实模型完整生成链路验收。

# 甘特箭头与流程图拖动连线修复

本次只调整图表连线与拖动落点；页面分区、业务依赖、排期和版本确认交互保持原有行为。

- 甘特图：FS 连线从前置任务右侧出发，避开任务条，从后续任务左侧进入。任务同日衔接、提前/延迟、多个前置任务和里程碑均使用一致的右向箭头。同一后续任务只绘制一个箭头头部，避免叠黑；箭头大小独立于粗边框，分隔线位于连线下方。
- 流程图：保留原有节点端口及接入方向；拖动时基于当前节点位置计算正交路径，避开节点，并清除零长度与多余共线折点，不再逐次插入折点。相连标签同步调整，无关连线保持原样。松开鼠标时读取最终落点，避免使用滞后的拖动状态。
- 预览、模板缩略图与导出继续使用同一个 Diagram。流程图修改后的折点仍保存在完整版本快照内。

## 验证

- `npm run quality` 通过：27 项后端测试、89 项前端测试、契约生成核对、类型检查和构建。
- 新增回归覆盖 DOWN/RIGHT 各 40 次往返移动、端口与标签稳定、无关边不变、直线节点交换前后位置、甘特同日衔接/汇入/里程碑/提前/延迟。
- Chrome 无头浏览器真实鼠标拖动横向和纵向流程图，反复移动并确认形成 v2；松开前后路径一致，预览与 SVG 导出路径一致，序列化重开后路径一致。浏览器未出现页面脚本错误。
- 已生成并检查 PNG/SVG，记录 1440×900 与 1920×1080 工作台截图。甘特样例按问题截图的任务关系构造，流程样例来自仓库；本次没有调用外部模型。

运行浏览器回归：在已有前端开发服务上执行 `node scripts/verify-connectors.mjs`，可通过 `BIAOSHU_WEB_URL` 和 `PLAYWRIGHT_MODULE` 指定服务地址及 Playwright 模块。

证据：[甘特 PNG](evidence/connectors/gantt.png)、[纵向流程 PNG](evidence/connectors/flow-down.png)、[横向流程 PNG](evidence/connectors/flow-right.png)，同目录含 SVG、项目快照与两个视口截图。

边界：本次支持在可用通道内避开节点；若用户把节点互相重叠，连线保留端口方向，但不能保证完全避让。未验证其他操作系统或浏览器。
